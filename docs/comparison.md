## 개요

### 비교 대상 애플리케이션

**부동산 구매 전략 AI 에이전트 시스템**
- 30대를 위한 현실적인 주택 구매 전략 제시
- 최신 부동산 정책 조사 및 분석
- 대출 계산 및 재무 계획
- 세금 시뮬레이션
- 종합 전략 수립

### 에이전트 구성

모든 프레임워크는 동일한 5개 에이전트를 구현:

1. **Research Agent**: 웹 검색을 통한 정책 조사
2. **Policy Analyst**: 규제 분석
3. **Financial Advisor**: 재무 계획
4. **Tax Specialist**: 세금 계산
5. **Strategy Coordinator**: 종합 전략 수립

## 프레임워크별 특징

### 1. LangGraph

**개요**
- LangChain 생태계의 일부
- 그래프 기반 워크플로우
- 명시적인 상태 관리

**핵심 개념**
```python
# StateGraph를 사용한 워크플로우 정의
workflow = StateGraph(AgentState)
workflow.add_node("research", research_node)
workflow.add_node("policy", policy_node)
workflow.add_edge("research", "policy")
```

**주요 특징**
- ✅ 복잡한 워크플로우 표현에 적합
- ✅ 명시적인 상태 전달
- ✅ 시각화 가능한 그래프 구조
- ✅ 조건부 라우팅 지원
- ❌ 학습 곡선이 다소 가파름
- ❌ 보일러플레이트 코드 많음

### 2. Crew.ai

**개요**
- 역할 기반 에이전트 협업
- Task와 Agent 분리
- 선언적 정의

**핵심 개념**
```python
# Agent와 Task를 선언적으로 정의
agent = Agent(
    role="부동산 정책 연구원",
    goal="최신 정책 조사",
    backstory="...",
    tools=[search_tool]
)

task = Task(
    description="...",
    agent=agent
)
```

**주요 특징**
- ✅ 직관적인 역할 기반 설계
- ✅ 간결한 코드
- ✅ 에이전트 간 협업 자동화
- ✅ 빠른 프로토타이핑
- ❌ 세밀한 제어 어려움
- ❌ 복잡한 워크플로우에서 제약
- ❌ 디버깅 어려움

### 3. Strands Agents (Custom Pattern)

**개요**
- 경량 에이전트 패턴
- 명시적 상태 전달
- 최소한의 추상화

**핵심 개념**
```python
# 간단한 클래스 기반 에이전트
class ResearcherAgent(BaseAgent):
    def execute(self, context: Dict) -> Dict:
        # 로직 구현
        return result

# 순차 실행
result = researcher.execute(context)
context.update(result)
result = analyst.execute(context)
```

**주요 특징**
- ✅ 가장 간단한 구조
- ✅ 완전한 제어 가능
- ✅ 디버깅 용이
- ✅ 낮은 학습 곡선
- ❌ 모든 것을 직접 구현
- ❌ 고급 기능 부재
- ❌ 확장성 제한

## 아키텍처 비교

### 워크플로우 실행 방식

| 항목 | LangGraph | Crew.ai | Strands |
|-----|-----------|---------|---------|
| 실행 모델 | Graph-based | Sequential/Hierarchical | Sequential |
| 상태 관리 | TypedDict State | Internal | Manual Dict |
| 에이전트 간 통신 | Edge를 통한 전달 | Context 자동 전달 | 명시적 전달 |
| 병렬 실행 | 지원 | 제한적 | 미지원 |
| 조건부 분기 | 완전 지원 | 제한적 | 수동 구현 |

### 코드 복잡도

**LangGraph**
```python
# 약 150줄 (graph.py)
- StateGraph 정의
- Node 함수들
- Edge 연결
- 상태 타입 정의
```

**Crew.ai**
```python
# 약 100줄 (crew.py + agents.py + tasks.py)
- Agent 정의 (간결)
- Task 정의 (간결)
- Crew 구성
```

**Strands**
```python
# 약 200줄 (workflow.py + agents.py)
- Agent 클래스들
- Workflow 클래스
- 수동 오케스트레이션
```

## 개발 경험 비교

### 학습 곡선

**난이도 순위**: Strands < Crew.ai < LangGraph

1. **Strands** (⭐️☆☆)
   - Python 기본 클래스만 이해하면 됨
   - 프레임워크 특화 개념 없음
   - 30분 내 시작 가능

2. **Crew.ai** (⭐️⭐️☆)
   - Agent, Task, Crew 개념 이해 필요
   - 직관적인 역할 기반 모델
   - 1-2시간 내 시작 가능

3. **LangGraph** (⭐️⭐️⭐️)
   - Graph, State, Node, Edge 개념
   - LangChain 생태계 이해 필요
   - 4-6시간 학습 권장

### 디버깅 용이성

**Strands** > **LangGraph** > **Crew.ai**

- **Strands**: 순수 Python, 명시적 흐름
- **LangGraph**: Verbose 모드, 상태 추적 가능
- **Crew.ai**: 내부 동작이 추상화되어 디버깅 어려움

### 코드 가독성

**Crew.ai** > **Strands** > **LangGraph**

- **Crew.ai**: 선언적, 자연어에 가까움
- **Strands**: 간단명료
- **LangGraph**: 많은 보일러플레이트

## 장단점 분석

### LangGraph

**장점**
1. 복잡한 워크플로우 표현력 최고
2. 명시적 상태 관리로 예측 가능
3. 조건부 라우팅, 병렬 실행 지원
4. LangChain 생태계 활용
5. 시각화 도구 제공
6. 에러 처리 및 재시도 기능

**단점**
1. 학습 곡선 가파름
2. 보일러플레이트 코드 많음
3. 작은 프로젝트에는 과함
4. 의존성 많음

**적합한 사용 사례**
- 복잡한 다단계 워크플로우
- 조건부 분기가 많은 경우
- 장기 프로젝트
- 팀 협업 프로젝트

### Crew.ai

**장점**
1. 가장 직관적인 API
2. 빠른 프로토타이핑
3. 역할 기반 설계가 자연스러움
4. 코드 양 적음
5. 에이전트 협업 자동화

**단점**
1. 세밀한 제어 어려움
2. 복잡한 워크플로우 제약
3. 디버깅 어려움
4. 내부 동작 불투명
5. 성능 오버헤드

**적합한 사용 사례**
- 간단한 다중 에이전트 협업
- 빠른 POC (Proof of Concept)
- 역할이 명확한 태스크
- 초보자 프로젝트

### Strands (Custom Pattern)

**장점**
1. 가장 간단한 구조
2. 완전한 제어 가능
3. 디버깅 매우 용이
4. 최소 의존성
5. 최고의 성능
6. 낮은 학습 곡선

**단점**
1. 고급 기능 직접 구현 필요
2. 확장성 제한
3. 표준화 부족
4. 병렬 처리 등 직접 구현
5. 유지보수 부담

**적합한 사용 사례**
- 단순한 순차 워크플로우
- 성능 중요 프로젝트
- 완전한 제어 필요 시
- 작은 팀/개인 프로젝트

## 결론

### 최종 권장사항

1. **대규모 복잡한 시스템**: **LangGraph**
   - 복잡도 관리, 확장성, 유지보수성 우수

2. **빠른 개발/프로토타입**: **Crew.ai**
   - 최소 코드로 빠른 검증

3. **성능 중심/단순 워크플로우**: **Strands**
   - 최고 성능, 완전한 제어

### 본 프로젝트에서의 선택

부동산 구매 전략 시스템의 경우:

**프로토타입 단계**: Crew.ai
**프로덕션 단계**: LangGraph

이유:
- 초기에는 빠른 검증 (Crew.ai)
- 복잡도 증가 대비 확장성 (LangGraph)
- 30대 사용자 경험 최적화를 위한 세밀한 제어
